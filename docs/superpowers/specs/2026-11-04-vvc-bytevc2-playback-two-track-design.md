# VVC（bytevc2）播放两轨决策设计

2026-11-04。目标：bytevc2 锁定集在电视上可看，行为符合既有兜底 UX（PR #48 语义）。

## 背景

- video_tab 供给按集锁定：部分集只有低档 bytevc2（VVC/H.266）+ bytevc1 1080P，竖屏 1080×1920 超出硬解 1088 上限降无可降，请求侧无解（见 2026-11-02-portrait-bytevc2-supply-design.md）。
- 软解直读路线已在 `feature-vvc-softdecode-bench` 实现（基准管线 + 集成 SwVideoController + 挂死修复），Sony BRAVIA（MT5891）基准全档 ≥4× 30fps 门槛（网络瓶颈下限）。
- 2026-11-03 用户实测旧集成包（挂死修复前构建）体验不行——挂死属于已修复问题，**修复版尚未被实测**。
- 本设计把两条候选路线固化为「主路线验收 + 后备路线存档」的两轨结构，由实测数据裁决。

## 主路线：软解直读（验收轮 2）

现状：实现完成（含 2026-11-03 挂死修复：解码线程 2→1、探速看门狗 25s、首帧看门狗 10s、会话级集黑名单）。

验收测试（用户自装实测）：

1. 用 `outputs/debug/hongguotv-tv-0.1.15-56-swdecode-hangfix-debug.apk` 在当初出问题的盒子上重播同批 bytevc2 锁定集（含十八岁太奶奶第五部 EP7）。
2. 观察项：能否起播、起播耗时、音画同步、seek 正确性、发热；若再卡死，记录集 id 与卡住提示（看门狗应在 25s 内自动放弃并降级，不得永久挂住）。
3. 最弱盒子加跑 `outputs/vvc-bench/vvcbench-0.1.0-bench-debug.apk` 补 fps 天花板数据（注意 fps 为网络瓶颈下限；stsd 宽高字段为 0 显示 0x0 属已知显示瑕疵，不影响 fps）。

裁决标准：同批集可稳定起播、音画同步可接受、无挂死 → 软解走 PR 合并，伴机方案封存。仍不达标 → 启动后备路线。

## 后备路线：伴机转码（本设计存档，仅在软解验收不达标时启动）

### 架构（方案 A：URL 中转型轻伴机）

- 伴机：零业务逻辑小服务（FFmpeg 7+ + HTTP），无登录态、无取源、无身份逻辑；URL 与请求头仅存内存。可打包为 jar 在 macOS/Windows/Linux 运行，不绑设备。
- TV 端：bytevc2 兜底判定处新增分支——发现伴机则转发直链+请求头，换取 HLS 由现有 ExoPlayer 路径播放；伴机不可用则回退现有兜底 UX，行为完全向后兼容。
- 已否决：本机 FFmpeg 转码（比已实现的软解直读 CPU 严格更贵、无收益）；重伴机自取源（凭据扩散、代码重，仅当直链绑定设备时启用）；投屏模式（iOS 无系统级 VVC 解码、UX 割裂）。

### 伴机接口（仅监听局域网）

- `GET /health` — 版本、ffmpeg 能力（VVC 解码器自检）、占用状态。
- `POST /session` — body：直链 + 请求头 + 起始偏移；启动 ffmpeg 软解 VVC → 转 H.264（分辨率跟随源，竖屏保持竖屏；音轨 AAC copy）→ 返回 `{sessionId, hlsUrl}`。
- `POST /session/{id}/seek` — 按新偏移以输入侧 `-ss` 重启 ffmpeg。
- `DELETE /session/{id}` — 结束会话并清理临时分段。
- 转码参数：H.264 1080p 封顶、2s 分段 HLS、单档画质（YAGNI）；同时仅 1 个活跃会话，被占明确拒绝。

### TV 端改动

- 新增 `RelayClient`：mDNS 发现（`_guoying-relay._tcp`）+ 手动 IP 兜底；缓存已配对伴机地址；首次发现弹一次确认并记住。
- seek：目标超出已转码区间即调 `/seek`，播放列表刷新后续播。
- 提示与降级：加载时显示「正在由伴机转码」；伴机失联/占用/转码过慢/直链过期（重新解析重试一次后仍失败）一律降级回现有兜底 UX。

### 安全

- 首次配对交换简单 token，防局域网滥用；伴机不落任何凭据；仅局域网监听。

### 前置探针（启动后备路线时先做）

1. 直链可转移性：TV 解析的 bytevc2 直链从局域网另一设备带相同请求头能否拉流（HTTP 200 且确认为 bytevc2）。
2. FFmpeg 软解冒烟：ffmpeg 7+ 实解该流 10 秒转 H.264，验证解码器识别与 ≥1x 实时速度。
3. 探针为独立脚本、凭据走环境变量不入库；任一失败且无绕法 → 回到重伴机方案（方案 B）再评估。

### 测试与发布（后备路线）

- 伴机：会话管理/seek 重启单测（假 ffmpeg 模拟）+ 本地 VVC 样例集成冒烟；TV 端 RelayClient 与决策点单测。
- 伴机独立版本号，不占 TV versionCode；发布形态 fat jar + README（ffmpeg 7+ 安装要求）；分支 `feature-relay-transcode`。
