# 果映 TV 原生客户端

工程：Kotlin + Android View + Media3。最低 Android 6.0 / API 23；compileSdk、targetSdk 为 36。安装标识 `io.github.tsukiyo_zero.guoyingtv`，与旧原生包 `com.hongguotv.nativeapp`、React Native 包 `com.hongguotv` 的数据独立。Kotlin namespace 暂保留旧命名，Manifest 使用完整 Activity 类名，真正安装标识以 APK 的 applicationId 为准。

当前正式版本为果映 TV 0.1.28 / versionCode 69，使用新包名。旧包名的 0.1.28 / 48 保留历史发布记录；新包需单独安装，不能覆盖旧包名；本机数据与登录态不自动迁移。备份恢复底层代码仍在，但当前设置页未接入入口，尚不能提供完整的图形迁移流程；重新登录后可获取账户内容。本机记录与账户内容不同，不能据此宣称本机记录已迁移。保持原签名与 Android 6 v1。

桌面图标与应用内标识采用 C3 蓝紫渐变果实银幕图，TV 启动器提供「果映 TV」横幅。主图与生成提示词见 [品牌资源](artwork/README.md)；多密度桌面图标覆盖 Android 6+，本轮使用完整位图，不依赖透明拆层或自适应前景。

功能介绍见 [项目主页](../README.md)，工作约定见 [开发流程](../CONTRIBUTING.md)。

## 首页刷剧

当首页提示“暂时没有新的推荐”时，点“换一批”会重新建立当前来源的推荐会话，并重置该来源的服务器游标与首屏缓存，但保留最近 540 条去重记录，避免继续沿用卡住的状态；连续三批仍重复则提示，不直接循环播放旧批次；去重窗口之外仍可能出现旧作品。正常换批仍继续原游标，其他来源和账号数据不受影响。

登录态恢复及账号校验完成后，首页才读取对应身份的续刷缓存，避免启动时临时未登录状态清除账号记录。账号校验失败时可临时匿名浏览，但不读写续刷缓存；恢复成功后继续使用原账号记录。

冷启动会按当前登录身份和推荐来源恢复上次的分页及最近 540 条去重记录，继续读取后续推荐。首屏缓存命中、正常加载与直接切到预加载作品都会记录当前选择，避免漏记后重启又回到相同开头；推荐、漫剧、真人剧互不覆盖，账号变化清空旧身份缓存。记录只在本机使用，不向平台上报试播曝光或正式观看历史。去重范围同时包含已获取的分页内容，续刷不保证精确恢复到上次画面或下一部未看作品；服务端仍可能重复推荐，清除数据、账号变化或记录超出窗口后也可能重新出现旧作品。

播放前先完成一次匿名设备注册，首页与正式播放共用平台返回的设备 ID、安装 ID 和设备 Cookie；同一应用进程内复用，不再随机生成未注册 ID。注册不登录账号、不发送短信，身份仅保留在内存，不进入本机历史或备份。取消页面请求仍可取消注册，注册失败后不使用随机 ID 继续请求播放，并显示「播放设备注册失败」；后续播放操作可重新尝试尚未成功的注册。新进程首次播放需要完成注册，平台不可达时仍可能失败。

首页进入全集时可一次性交接 15 秒内刚取得的同集模型，减少重复请求。最多六条仅在当前注册会话内存中保留，不落盘；首次交接后移除，同一仓库的后续重试仍重新获取，过期或身份改变不再复用。

首页与正式播放共享注册会话和签名上下文。签名器在该会话内复用，进程 nonce、启动时间保持一致，请求时间戳和最终查询/正文仍逐次重新签名。按会话路径健康度选择 GET video_tab 或三条 POST 备用路径：近期成功路径优先，空响应路径冷却 30 秒，其他临时故障短暂避开。前台最多四次候选请求，不同路径直接切换，不在同轮重复撞同一地址；注册与首选/备用主模型读取共享 8 秒绝对截止时间。已知路径全为空时，前台可在剩余请求和时间额度内恢复一次匿名身份；失败保留原身份；注册失败后冷却 5 秒，替代身份仍无模型则冷却 30 秒，后续前台调用才重新开放一次额度，不增加后台循环。取消任务不累计空响应或占用身份恢复额度。后台只轻量尝试一次，模型阶段 2 秒，冷却路径全不可用时不发请求，不主动注册替代身份，也不累计前台连续失败次数。

首页初次资源准备及最多两次空响应恢复共享 15 秒网络额度。正式播放初次资源准备及默认快速恢复共享 20 秒网络额度，快速恢复最多三次；其后保留错误与操作，较长的慢段五次恢复需要主动选择“继续等待恢复”。网络预算包含对应请求作用域内的模型和视频索引读取，不包含播放器后续解码和持续媒体播放；截止时间或次数耗尽不会继续自动发起整轮请求。手动立即重试开启新预算；已出画面后的新故障也开启新的恢复窗口。

播放页加载与恢复状态保持可见；恢复时保留原失败原因，直到真正输出首帧才清除，STATE_READY 不提前当作已恢复。恢复中的用户可取消或返回选集，返回键也能退出准备阶段；自动恢复复用现有播放视图以尽量保留旧画面，首次播放则显示准备阶段。错误诊断带固定路径代号 G/P、HTTP 状态、应用读取的正文字节数、协议和注册结果，不包含身份、Cookie、签名、媒体地址或响应原文。`reg=ok` 只表示替代身份就绪，不表示已出画面。

2026-11-06 有界采样仍能观察到 HTTP 200/0 字节，真实新连接和静默一分钟均不能保证恢复；不能把全部异常确定归因于单一服务端规则。本轮效果仍待电视实机验收，调查与边界见 [PLAYBACK_STABILITY.md](PLAYBACK_STABILITY.md)。

首页仍试播第一集，不把试播当作正式观看记录。「观看全集」进入详情后，续播按钮比较本机和当前账号已读取的云端历史，使用更新时间较新的记录（同时间优先本机）；无记录时从第一集开始。云端范围仍限当前账号最近已读取的 50 部，不保证未加载的云端记录可用。

账户历史直接播放时使用该条云端进度；云端分集 ID 无法匹配官网分集列表时，按有效云端集号定位，并保留时间位置。ID 可匹配时优先采用 ID，避免分集顺序变化造成错集；集号无效时不强行套用时间。本机历史继续使用本机 checkpoint，云端记录不预先写入本机历史。

切回本次已浏览的推荐、漫剧、真人剧时恢复该来源的列表、分页和选中作品，试播从头开始；「换一批」仍请求新批次。账号变化清空三类来源状态。另有按登录身份隔离的 10 分钟首屏元数据缓存，每来源最多 30 部，仅保存卡片与经过详情核验的首集 ID/总集数；不保存播放 URL、服务端游标或凭据。缓存命中先试播缓存作品，后续分页以新的服务端会话获取并去重，过期或损坏时直接联网。

播放模型若包含完整可用的 video_meta、encrypt_info 与媒体地址，直接选流和派生内容密钥；缺少可用项时保留原备用接口。首页先在一个 256 KiB 范围请求中消费 32 KiB，再按实际索引大小继续读取，索引超过范围时补取；正式全集播放仍采用原首段大小。首次进入、冷缓存和缺少可靠首集标识的分类仍有必要的联网请求。

首页推荐、漫剧与真人剧均试播第一集。试播播放失败若属解码类错误（如盒子虚报竖屏能力导致 1080P 竖屏运行时失败），会把失败档位写入设备能力记录（与正剧共用经验表）并自动换低档重载（状态栏提示"正在自动切换"，每剧至多三轮，且仅在学习到新的能力记录键时继续；新设备竖屏首播可经 1080P→720P→480P 收敛到可看档位），仍失败才显示「试播暂不可用」。第一集本身没有电视可解码档（bytevc2 锁定集）时自动后移到第二、第三集中首个可解码集作为试播内容并标注「第一集暂不支持电视播放 · 试播第 N 集」，前三集都不可解时显示「该剧暂无电视可解码的清晰度」。保留前一部和后三部的播放地址与完整索引缓存（先消费 32 KiB，再补齐完整索引，不等待整个 256 KiB 范围响应）；当前视频正在播放且缓冲达到 1.5 秒后，启动下一部的预加载。完成地址和索引解析后立即交给 Media3，无需等额外固定 1 MiB 下载；Media3 提前解析轨道并将下一部约 1.5 秒的媒体样本放入播放器缓冲；后两部在当前作品稳定 3 秒、6 秒后逐步准备，后台模型失败不循环重试；播放器预加载总缓冲目标为 4 MiB。沿用一个播放实例，不为每部作品建立独立解码器。

首页当前作品读取播放信息遇到空响应时，最多自动恢复两次，间隔为 2 秒、5 秒；每次使用上述有界模型读取流程，并共享本次 15 秒网络准备额度。倒计时显示在原状态栏，不弹窗、不抢焦点；可点“立即重试试播”取消倒计时并主动重试。两次仍失败后显示原因和脱敏接口诊断，等待手动选择。不自动重试目录读取、明确业务/HTTP 错误、解码错误或后台预加载。切换作品、分类、换批、离开前台和关闭页面会取消倒计时及过期请求；手动重试开始新的两次预算。关闭自动试播时，即使资源恢复成功也保持暂停。

上下换剧时复用缓存；若目标作品仍在预加载，则接续该任务，失败后退回前台加载，避免取消后重复解析与下载。同一 HTTP 分段中的视频数据边到达边交给播放器，不等待整个 512 KiB 分段完成。切换类型、换批、离开页面或退出仍取消过期任务并清理资源。

本轮参考本地官方 App 6.5.5.32 中可识别的 TTVideoEngine、DataLoaderHelper 和短视频预加载组件，采用独立实现；静态分析不能确认官方实际启用的策略或参数。Media3 接入依据 [Android 官方预加载文档](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager)。此前首页加载优化已经用户验收并纳入正式 0.1.28；本轮分级预加载、签名上下文及首次路径优选仍待电视实机验收。没有与官方 App 进行设备测速对比，不承诺固定首帧耗时；缓存未命中时仍需要必要的推荐、播放地址和视频索引请求。

日志只记录 `Home recommendations`、`Home category`、`Home detail`、`Home starter-cache hit`、`Home play-address`、`Home promoted in-flight preload` 与 `Home first-frame` 等阶段信息，不打印播放地址或账户信息。`first-frame` 从交给播放器开始计时，不包含此前推荐及地址请求耗时。

## 正式播放与下一集

正式播放一次请求当前集和后两集的播放模型，仅将服务端按分集 ID 返回的后续模型保留在内存，最多 6 条、60 秒过期，领取即移除。连续切集或预加载可省去这次模型请求，缺失或过期仍单独获取；重试同一集不会反复使用同一个旧地址。不额外下载后两集的完整视频，不持久化媒体地址或密钥。批量接口已作匿名实测，实际设备效果待验收。

自动连播按倍速折算后剩余 30 秒内准备下一集，仍要求当前播放稳定、有足够缓冲、前台且非计费网络。播放地址复用当前 Repository 的设备标识与匿名会话；视频传输保持独立的连接池和请求调度器，继承正常播放的超时，取消预加载不会取消当前集的请求。

下一集先读取 32 KiB，并按实际 MP4 索引长度继续补齐；索引可用后立即加入同一播放器队列，由播放器继续缓冲，不等待额外固定 2 MiB。手动或自动切集时，若对应准备任务尚未结束，则在后台接续该任务，不先取消重来；准备失败时仍可回退到正常获取流程。退出、切换其他集或取消播放会取消接管任务并关闭迟到资源。已经入队的下一集保持原有同播放器接续、进度保存与定时停止规则；不承诺所有网络、格式和电视均无缝切集。

## 遥控器搜索

找剧页保留原组合筛选，点击「屏幕键盘」进入独立搜索工作区；提交关键词后也进入该布局。左侧为 6 列 A–Z/0–9 键盘，提供删除、清空、搜索、系统中文输入、手机输入和返回分类；中间为服务端联想及最多 8 条最近搜索，右侧为连续分页海报结果。结果按显示宽度使用 2/3/4 列，窄屏时缩小侧栏，键盘区可纵向滚动，不挤占组合筛选。

字母按键输入小写字符，插入/删除遵守光标选区；删除按 Unicode 字符处理，不拆开代理对。输入最多 80 字，联想仍延迟 350ms 并取消旧请求，选择候选词或历史后明确搜索；不自动把字母当作保证可匹配的拼音首字母。左右可在键盘、候选与结果之间移动，结果首列向左返回词条区；返回退出搜索回到组合筛选。中文输入调用系统输入法，手机输入仍需可互通局域网。布局与控件回归覆盖 API 23/26，遥控器手感需用户验收。

## 连续浏览

找剧分类接近底部时按服务端返回的偏移和会话游标继续加载，关键词搜索按服务端页码继续加载，结果均去重追加。分类和搜索遇到连接超时、连接中断、域名解析失败或 HTTP 500/502/503/504 时，等待片刻后自动重试同一请求一次；其他 HTTP 错误或响应格式异常不自动重试。仍失败时保留当前列表，底部显示错误类型并可手动重试。搜索返回分类、从详情返回列表时恢复选中作品。排行榜使用六列海报网格，沿用完整榜单和全榜题材筛选，卡片标注原榜名次与可用热度，连续浏览不改变原始名次。榜单请求在内存中携带站点重定向下发的会话 Cookie（不落盘），读取使用收紧的超时并在瞬时失败时自动重试一次。四个榜单各自独立并行加载、互不取消：会话内 10 分钟 TTL 内切换直接展示缓存零请求，过期后展示旧榜单的同时后台静默续期，用户点刷新才强制重拉；切换榜单永不进入模态等待。找剧分类页移除常驻加载／回顶按钮，接近底部自动加载，失败才显示重试；分类页按返回回顶并聚焦「找剧」，再次返回按原导航规则离开。搜索结果与排行榜保留各自原有返回和回顶操作，长按确认或菜单键管理作品。

输入停顿 350 毫秒后请求官网公开联想接口，最多显示 8 个候选；服务端可将部分拼音输入匹配为中文剧名。选中候选后按该中文词搜索，不自动打开详情；直接搜索、搜索历史与手机输入仍可使用。联想请求使用独立可取消任务，不中断当前结果分页；输入变化、离开页面或切到后台时取消过期任务，失败不阻止直接搜索。不承诺任意拼音、首字母或错别字都能匹配。

分类使用 App 分类接口的真实分组：类型（全部、真人剧、漫剧、AI 剧）、主题、设定、背景、推荐排序、受众、上新时间，以及服务端提供时的作品状态。每组单选，不同组的条件组合提交到服务端，不是只筛选已加载作品；每行「全部」清除本组条件，受众「女频」的值为 `0`，与「全部」区分。切换内容类型会清除旧类型的条件并重新获取分组，重置会回到全部类型、全部条件。

遥控器左右选择同组条件，上下切换分组；较小屏幕可上下滚动筛选区。进入海报列表保持筛选展开状态，可手动收起；列表首行向上可到筛选控制按钮；搜索或详情返回后保留组合条件、列表、选中作品及筛选行滚动位置；选中高亮始终依据实际筛选条件重绘，横向超出可视区域的选中项会恢复到可见范围。分类仍最多加载 100 批，未返回的分组或选项不自行补造。可用高度不足时海报缩小，标题改为单行，必要时隐藏副信息以保留列表空间；完整作品信息仍可进入详情查看。旧网页分类入口继续保留给首页兼容路径及 Mac 客户端，本轮未改变它们的行为。

界面使用 Android 系统 GridView 回收离屏卡片，搜索最多 100 页、分类最多 100 批；切换分类、题材或关键词会重新从首批读取。账户收藏、历史和预约的读取范围不变。遥控器手感仍需用户在电视上验收。

## 构建环境

需要 JDK 17、Android SDK Platform 36 和对应 Build Tools。设置 `JAVA_HOME`、`ANDROID_HOME`，或在本地 `local.properties` 配置 SDK 路径。可以用 Android Studio，或在支持 Android/Gradle 的 IDEA 中打开本目录；也可直接使用终端。

以下命令均从仓库根目录执行：

```sh
# 回归检查和开发 APK
./kotlin-tv/gradlew -p kotlin-tv :core:test :app:testDebugUnitTest :app:assembleDebug :app:lintDebug

# 只生成开发 APK
./kotlin-tv/gradlew -p kotlin-tv :app:assembleDebug
```

默认产物：`kotlin-tv/app/build/outputs/apk/debug/app-debug.apk`。

## 版本与签名

调试时保持 `app/build.gradle.kts` 的 versionName/versionCode 不变，通过文件名区分测试包；正式发布由统一入口自动递增版本。环境变量 `HONGGUOTV_VERSION_CODE`、`HONGGUOTV_VERSION_NAME` 会覆盖文件中的默认值。当前正式版为 0.1.28（versionCode 69），后续正式发布再递增。分支名、APK 文件名或 Git 标签不会自动改变 APK 内部版本。

开发 APK 使用本机 Debug 签名。电视已经安装的版本只能由相同包名、相同签名的新版覆盖；换电脑或改用其他签名可能无法覆盖安装。不要删除、替换现有签名密钥，不要将密钥或密码提交到仓库。

Release 构建读取 `kotlin-tv/keystore.properties`（已忽略）或对应环境变量：

| 本地配置字段 | 环境变量 |
| --- | --- |
| storeFile | HONGGUOTV_KEYSTORE |
| storePassword | HONGGUOTV_STORE_PASSWORD |
| keyAlias | HONGGUOTV_KEY_ALIAS |
| keyPassword | HONGGUOTV_KEY_PASSWORD |

`storeFile` 建议填写已有密钥的绝对路径。默认 assembleDebug 使用本机 Debug 签名；交付测试包另用原签名签署并核验，不能只根据文件名判断签名。

## 正式发布与在线更新

从仓库根目录使用统一入口：

```sh
# 只读预演：核对两平台已发布版本、标签和草稿，输出版本规划
python3 scripts/release-tv.py

# 功能已验收并合入 main、工作区干净后，明确执行正式发布
python3 scripts/release-tv.py --publish
```

正常发布无需手动指定版本；自动执行版本提交/PR、构建检查、原签名与 v1 校验、双平台标签和附件发布及 Latest 核验。首次需要配置已有凭据、工具链和原签名；中断后按记录使用 `--publish --resume <版本>`，不另开版本。新包名过渡由更新说明明确提示单独安装，不将旧包当作新包覆盖升级。

`./scripts/build-kotlin.sh` 只做本地 Release 构建和配套清单生成，不发布。它按实际版本写入 `outputs/releases/<tag>/`；调试期间优先使用 assembleDebug，避免用相同版本覆盖本地保存的正式包目录。完整配置与故障恢复见 [AUTO_UPDATES.md](AUTO_UPDATES.md)。

用户后续在同包名果映 TV 内可从 GitCode 检查、下载并校验新版，由系统确认安装。GitHub/GitCode Release 也可手动下载；本地测试包没有上传正式渠道，不会被应用内更新获取。

## 验证边界

框架回归覆盖 API 23、API 26。具体电视的解码、声音、遥控器和实际账号同步仍需要设备验证。由维护者改代码、自动化检查和打包，用户安装测试并反馈截图；不自动操作用户模拟器。

竖屏与横屏视频都按设备解码能力选流：启动时探测 AVC/HEVC 解码器上限（logcat 搜索 `Decoder capabilities`），选流优先跳过盒子声明解不了的档位，并在播放前用 MP4 头里的实际编码尺寸复核，超出上限时自动沿清晰度阶梯降档（HUD 显示"自动降清"）。部分盒子会虚报解码能力（声明可解、实际失败）：此类运行时失败会按"编码+编码尺寸"记入持久化的设备能力记录（跨重启、跨剧集生效，竖屏失败不影响横屏），并当场自动降档重试（每集至多 2 次，无需手动切换），logcat 出现 `Learned decoder failure` / `Auto downgrading`。播放失败面板的"尝试 xP"按钮指向阶梯里真实存在的更低档（没有更低档时显示"本集没有更低清晰度可用"且不出现按钮）；"播放设置 → 重置设备能力记录"可清除学习结果（应对盒子固件升级）。

2026-11-04 补充验证：部分集数的原始播放模型只提供 bytevc2。对于 fallback 响应全部档位均为 bytevc2/bvc2 的情况，客户端额外请求一次兼容模型（`codec_type=0` 与 `force_codec=h264`），按实际返回编码选档；参数名称不保证返回 H.264。issue #56 指定作品第 71、72 集实测可获得 H.265，视频头为 hvc1、1254×720，真实电视解码效果仍待验收。已有可用档位、空列表或未知编码不触发这次兼容请求，不引入官方解码库。该兜底不覆盖所有混合编码或设备能力问题。对这类确定性失败：本集没有任何可解码档时立即显示「本集低档为 VVC（bytevc2）编码，电视无法解码，可尝试其他集数」，不进入 8 次自动恢复空转，「立即重试」保留（服务端转码推进后该集供给可能翻转为 bytevc1）。首页试播（第一集）遇到该类集时自动后移：依次尝试第二、第三集，用首个可解码集作为试播内容并标注「第一集暂不支持电视播放 · 试播第 N 集」，前三集都不可解时显示「该剧暂无电视可解码的清晰度」。试播解码失败的自愈从每剧一次改为最多三轮迭代（仅当学到新的能力记录键时才继续重载），新设备首播竖屏可在 1080P→720P→480P 间自动收敛到可看档位。

播放中持续监测视频帧处理偏移（logcat 搜索 `Video frame offset` / `Resync after audio/video drift`）：平均偏移持续超过 150ms 时自动对当前位置做一次无感重同步（间隔至少 30 秒），用于消除随播放时长累积、倍速下更快的音画不同步。

排查播放、账户或旧系统兼容问题前，先读 [开发排查笔记](../docs/DEVELOPMENT_NOTES.md)。第三方来源与许可见 [NOTICE.md](NOTICE.md)。

评论与弹幕调试入口和验收范围见 [SOCIAL.md](SOCIAL.md)。

### 启动与播放界面体验（当前开发分支）

- 设置 → 外观与操作：可直接选择首页、找剧、排行榜、收藏、观看历史、账户预约、设置七个页签作为启动页面；默认仍进入首页，不提供“记住上次”。
- 可关闭首页自动试播；关闭后切换作品会准备首集并保持暂停，点击“继续试播”才开始，正式播放不受影响。
- 正式播放按 ↑ 或菜单键直接打开操作菜单，不暂停播放，↓ 仍为选集，确定仍为暂停／播放。自动连播进入下一集时不自动显示标题和进度菜单，可照常用遥控器唤出。
- 播放控制栏采用两排按钮（播放／上下集，选集／评论／弹幕／设置），减少横向键程；正常播放时信息层约 4.5 秒、操作栏约 8 秒无操作后收起。暂停、错误提示和弹窗操作不强制隐藏；返回键仍可主动收起。
- 播放时钟支持关闭、操作时显示、始终显示，默认操作时显示；使用电视系统时间。
- 开发调试包不改变正式版本号，新增界面仍需电视实机验收。

- 通用列表选择弹窗采用深色圆角面板与独立选项行；启动页、时钟、倍速、清晰度和画面模式显示当前项勾选并默认定位，暖橙底色和左侧指示条表示遥控焦点。确定立即选择，返回取消；长列表可滚动。确认、登录和输入类弹窗保留原有交互，并统一深色面板。

- 设置页采用左侧“播放／外观与操作／账户／应用与更新”分类、右侧选项布局。左侧聚焦即切换内容，右键或确定进入选项，左键返回分类；返回键先回分类，再回顶部导航。分类与各分类的选项焦点在本次应用会话内记忆。自动连播、首页自动试播可在设置行直接切换，其他选项沿用选择面板。

- 设置页采用代码绘制的深蓝渐变背景、轻薄半透明卡片、名称与当前值左右对齐，以及暖橙焦点指示条；行内开关采用统一胶囊样式。选择面板沿用同一视觉语言，无实时模糊或背景大图；全站浏览页面、通用弹窗及播放面板共用配色；视频画面继续使用纯黑底。

- 设置页视觉细化：导航以暖橙下划线标记当前页，遥控焦点用浅橙框区分；四个分类均保留底面，卡片高度随内容收拢，标题保留细分隔线，选项以留白区分。选项焦点采用左亮右隐的三段暖橙渐变和渐隐描边，聚焦名称为纯白、当前值为浅橙；分类保留低透明深蓝底面，实际焦点使用暖橙渐变与浅橙细框，焦点移入右侧后保留淡橙当前分类标记。背景加入轻微平铺纹理；进入设置默认聚焦当前分类的选项，按左返回分类、第一行按上返回导航。

- 首页、找剧、排行榜、收藏、观看历史、账户预约、设置及详情统一深蓝渐变背景、暖橙导航与焦点、轻薄卡片；筛选、系列作品、搜索、评论、登录与更新弹窗以及播放选集沿用同一视觉语言。二维码保留黑白高对比度，播放器保留黑色视频底与原有控制逻辑。

- 视觉可读性：操作与选择弹窗使用接近不透明的深色底，避免海报干扰菜单文字；通用按钮使用浅暖橙细焦点框。作品预览未聚焦时显示选择提示，详情简介保留全宽两行摘要并增加行距。

- 设置选项聚焦采用暖橙色渐变；开关随整行聚焦显示浅橙细描边，仍保持整行一个遥控焦点。

- 切换账户内容页时不再弹出连接中提示，保留页面状态与失败反馈；首页试播区域使用黑底和聚焦描边，找剧筛选增加横向及行间留白。

- 找剧长筛选行保留一屏常用项及当前选项，右侧固定“全部 · N 项”入口；打开四列选项面板后可用方向键选择，确认应用，返回取消。短筛选行直接展示。

- 播放恢复修复（开发分支）：连续空响应触发匿名身份更新后，先重新尝试首选播放信息接口，再回退备用接口；首选接口成功后重置连续失败计数。默认快速恢复和主动继续等待策略见上文，尚待电视验证。

- 启动页设为观看历史或收藏时，本机内容直接读取本地记录，不再误入空关键词搜索请求；账户内容仍沿用账户刷新流程。

## 完整相关季与跨季连播（开发分支）

相关作品不再按 30 项截断，保留接口返回的有效项目，当前系列优先并按季序排列，其他同 IP 系列按剧名主体分组后排列；“全部季 / 相关作品”提供四列网格，支持滚动选择和待上线预约。入口数量不含当前季，不承诺接口未返回的季。

设置 → 播放新增“跨季自动连播”，默认关闭，需同时开启自动连播。最后一集播放进度过半后，读取并提示可靠匹配的下一季，在画面底部显示不抢焦点的单行提示；按 ↑ 打开操作菜单可取消本次跨季连播。播完后直接从下一季第 1 集开始，不弹窗或倒计时。离开前台、切集或睡眠停止会取消。无法可靠匹配、待上线或读取失败时停在结束页，不跳过缺失季、不按相关卡片顺序猜测下一季。尚待电视实机验收。

季号兼容“第39季 / 40季 / 第四十季”等尾缀写法，统一用于同系列排序与连续季匹配；仍要求剧名主体一致、季号连续且下一季唯一，不做任意相似剧名合并。

### 更新包签名兼容性修复（开发分支）

内置更新同时请求旧版证书收集标志与 Android 9+ 签名信息，兼容 Android 9/10 及部分电视系统解析 APK 文件时缺少签名字段的情况。优先比较当前签名，必要时读取旧签名字段；无法读取证书或签名不同仍阻止安装，并分别提示原因。包名、版本、最低系统版本及文件大小/SHA256 校验继续保留，尚待受影响电视实机验收。

已经受旧版校验影响的设备，需要从本仓库官方 Release 手动下载并覆盖安装包含修复的版本一次；无需卸载，保持同包名和原签名可保留本机数据。旧版不会因服务器更新而自动获得此修复。

### 首页连续换剧修复（开发分支）

未缓存作品上下切换后等待停留 300 毫秒再准备试播，继续切换或离开页面取消等待；已有缓存和在途预加载仍直接复用。首页推荐按实际选中的推荐标签统计分页条数，解析不再丢弃单批第 31 部之后的作品。连续重复推荐耗尽后，“换一批”重建服务器分页会话但保留最近 540 条去重记录；若仍无新作品则提示，不保证服务端持续提供新内容。上述边界有本地回归测试，快速刷剧恢复和推荐数量仍待电视验收。

账户历史读取失败与“账号没有记录”分别提示；空响应显示固定请求阶段（账号资料、历史列表或剧集资料）及 HTTP/字节数/协议，不包含账号身份或请求地址。刷新失败保留当前账号已加载的历史，不自动退出登录、不自动重试账号接口。重新登录能恢复不代表已证实登录态过期。

旧的未签名推荐请求在 2026-11-07 两轮采样中累计 50 部后重复；这不是服务端总体上限。补齐注册身份、完整签名与官方单列续刷分支后，实际客户端一轮连续取得 57 部不同作品，最后两页仍新增。保留耗尽提示与去重，不能承诺无限新推荐；用户账号与电视效果仍待验证。

参考用户提供的官方 App 7.4.3.32 静态调用链，默认推荐在首屏明确启用单列续刷且标识完整时，改走 `bookmall/cell/change` 并采用服务器 `next_offset`；旧游标快照自动重读入口且保留去重。分类接口与原缓存窗口保留。只换续刷接口而不补签名的样本仍在约 50 部后重复；完整签名与注册上下文组合验证已取得 57 部不同作品。不能宣称实现了官方兴趣反馈或保证无限推荐。核查与播放失败因果边界见 [官方 App 推荐协议核查](APP_RECOMMENDATION_REFERENCE.md)。

默认推荐与播放共用注册身份和 Cookie，推荐按 7.4.3.32 上下文稳定签名；账号 Cookie 仍隔离携带，明确 110 拒绝时保留原只读兼容形态。进程恢复或换注册身份后重读推荐入口但保留去重；签名、Cookie、设备身份及分页标识不进入日志。

### Android 6 电视更新安装兼容

更新安装优先使用内容 URI 授权，依次尝试标准入口与常见安装器组件。Android 6 另将已校验的 APK 复制到应用专属外部 Download 目录，再校验大小及 SHA256，作为旧式文件入口兜底；外部目录不可用时仍尝试内容入口，不新增存储权限或放宽私有目录权限。Android 7+ 不外发文件 URI。安装仍须系统确认，无法绕过未知来源限制。全部入口失败时提示尝试数量和失败类别，日志不含安装地址或异常正文。小米电视 4A L60M5-4A（Android 6）尚待实机验收；旧版需先手动覆盖安装一次修复包。
