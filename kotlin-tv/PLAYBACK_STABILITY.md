# 播放信息空响应：调查与恢复边界

## 2026-11-06 的有界采样

使用桌面 JVM 上的正式 `ContentRepository` 请求代码，取首页两部作品首集。每组交替读取四轮，轮间隔两秒；不输出作品 ID、设备身份、Cookie、签名查询或媒体地址。每组使用独立匿名会话，没有并发试播。诊断代码位于本机临时目录，不随应用发布。

前三组均出现同样序列：

| 轮次 | 首选 GET（b） | 备用 POST | 最终结果 |
| --- | --- | --- | --- |
| 1 | 有模型 | 未调用 | 成功，5 档 |
| 2 | HTTP 200、0 字节 | b 成功 | 成功，5 档 |
| 3 | HTTP 200、0 字节 | b 空，hl 成功 | 成功，5 档 |
| 4 | HTTP 200、0 字节 | b / hl / lf / b 全空 | 空响应异常 |

第三组在每次调用前清理诊断客户端的空闲连接；记录确认各次模型请求连接均不同，仍出现同样失败序列。这表明新连接不能消除该次空响应，不能将“换连接”描述成服务端问题的根治。

另一次正式恢复流程采样，在两轮全空后静默一分钟再请求获得成功，但同时触发了原有身份轮换，不能据此认定冷却有效。随后使用同一匿名身份、同一集，仅请求首选 GET 五次：初次获得模型，后面三次空；停止请求一分钟后第五次仍空。该组没有备用调用或身份轮换。

响应 Date 与本机时钟差约 0–1 秒。本次失败发生在播放模型请求阶段，尚未下载或解码媒体，不能归因于电视硬解码器。证据提示需关注身份与路径相关的服务端校验；尚不足以确定是频率、请求签名/指纹、身份限制还是网关策略，也没有验证全站同时不可用。

## 当前实现（后续用户反馈后的调整）

- **签名上下文稳定**：此前 playbackRequest 每次新建 Signer，使“进程 nonce”和启动时间随请求变化。现在同一注册会话复用签名器，跨首页/正式播放仓库实例也不重建；请求时间戳、正文摘要和签名仍逐次生成。注册身份改变后使用新的上下文。字段一致性修复本身不能证明服务端所有空响应的根因。
- **一次性模型交接**：首页进入全集时可复用 15 秒内刚取得的同集模型，最多六条仅在会话内存保留，领取即移除；同仓库后续重试强制重新获取，过期或身份改变不再交接。模型不写入日志或磁盘。
- **首次路径选择**：每个注册会话独立记录路径健康度，近期成功优先；空响应冷却 30 秒、其他临时故障短暂避开。前台总计最多四次候选模型读取，不重复同一路径；GET 不适用时仍保留一次 POST 探测。注册与这些调用共享 8 秒绝对截止时间，独立连接池避免 HTTP/2 合并重试连接。旧的 GET 加四次 POST 和固定域名循环已替换。
- **本轮内恢复**：连续空响应或已知全部路径空时，前台至多尝试一次注册替代身份；若有剩余请求额度，可在同轮完成，不先返回错误再重跑整轮。并发仍先原子标记，其他仓库已替换失败身份时复用。
- **后台隔离**：后台模型读取只尝试一次、最多 2 秒；所有路径都在冷却时不请求，不主动轮换身份，也不累计前台连续失败次数。后台记录的真实路径健康度仍供前台参考。
- **缓存保留与分级准备**：保留前一部、后三部的缓存范围；先准备下一部，当前播放稳定 3 秒、6 秒后再准备更远两部。保留同一在途任务晋升与相邻缓存复用，不为未观看作品反复恢复。
- **整次网络准备预算**：首页初次准备和两次空响应自动恢复共享 15 秒，正式播放初次准备和默认快速恢复共享 20 秒。该预算通过请求作用域的绝对截止时间覆盖模型及视频索引网络读取；不约束纯 CPU 工作、硬件解码和后续正常媒体播放。手动重试开启新预算。正式播放稳定后产生新故障时，开启新的恢复窗口。
- **状态与操作**：正式播放默认快速恢复最多三次；更长慢段等待需主动选择。错误原因、当前阶段及取消/返回操作持续到首帧输出；READY 不提前清除原因，重试不隐藏状态层。自动恢复尽量复用播放视图保留旧帧，初播显示准备状态；取消会使过期结果失效，不能稍后自行播放。

## 截图诊断格式

例如：`G:b=200/0B/h2 P:b=200/0B/h2 P:hl=200/0B/h2 P:lf=200/0B/h2 rotated=1 reg=ok`。

- `G` / `P`：首选 GET / 备用 POST；`b`、`hl`、`lf` 是固定域名短码。
- `200/0B/h2`：HTTP 状态、应用读取的正文大小、协议；大小为解压后的字节数。空白正文即使非零字节也视为空响应。
- `503/?B/h1`：HTTP 错误时未读取正文；`timeout/dns/io/cancel` 表示未完成读取，后者不包含底层错误消息。
- `/c100103`：首选接口返回的数字业务码；`/invalid` 表示非预期 JSON。零字节响应没有业务码，不能推断其具体原因。
- `rotated=1 reg=ok/failed/pending`：本失败期已尝试轮换，分别表示替代身份已就绪、注册失败、另一任务仍在处理。`ok` 不表示播放一定成功。

## 验证与验收

本地自动回归覆盖：签名进程上下文稳定且时间戳变化、身份更换后隔离、跨仓库共享成功路径、冷却与失效探测、同轮剩余额度内恢复、后台不循环读取/不注册、所有候选共享一个绝对截止时间、真实 HTTP/2 连接独立、首帧前状态不能被隐藏、快速恢复停止并提供主动继续选项、首页分级缓存与生命周期取消。保留 API 23/26 回归，不操作用户模拟器或电视。

用户安装原签名验收包后，重点核对连续翻剧的首次成功情况、前后切换是否顺畅、错误原因是否持续可见、取消后是否停止、较长等待是否只在主动选择后发生。失败反馈只需要截图和大致时间，不需要 Cookie、设备身份或账号凭据。尚不能声称已根治服务端空响应。

## 当前分支的真实小样本复测

路径优选已启用但仍逐请求新建签名器时，一组两部首页作品交替四轮有两轮获得模型、两轮全空。改为会话复用签名上下文后，同规模后续四轮均获得至少一档模型，第四轮在同一次读取内恢复身份后成功，未向调用方返回失败。后一次仍有候选路径零字节，不能理解为接口已不再出现空响应。

两组发生在不同时间，首页内容和服务端状态未完全固定，样本也很小，不构成严格的因果 A/B。该结果支持继续电视验收，不能单凭它认定签名上下文就是唯一根因，也不能据此承诺首次播放成功率。仅验证模型获取，没有运行用户模拟器或验证该采样的电视解码。

## 连续换剧状态修复（开发分支）

用户反馈快速刷剧后持续空响应、切到找剧再回来可恢复。代码核查确认：首页重建会清空 Repository 失败状态，旧逻辑一次注册恢复失败后必须等模型成功才重置，存在恢复额度长期锁死的缺口；这不证明服务端空响应的原因是频控。改为注册失败冷却 5 秒、替代身份仍失败冷却 30 秒，后续前台调用才开放一次恢复额度，不新增后台重试循环。取消任务不提交路径失败和连续空回合，取消中的恢复会释放本次额度。未缓存作品快速切换时增加 300 毫秒停留等待，避免每次按键都发起模型准备，原缓存窗口保留。服务端是否按身份或网络出口限制仍未证实，不能从 `reg=failed` 推断零 ID 或固定频控窗口。本轮尚待电视验收。
