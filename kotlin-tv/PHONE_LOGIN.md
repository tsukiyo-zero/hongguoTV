# 手机号登录区号与验证说明

## 当前列表依据

用户提供的官方登录界面连续截图可确认 14 项：86、852、853、886、60、65、62、95、63、84、855、81、82、971。TV 按截图顺序提供这些项，不将“尚未实号验证”作为删除截图已提供区号的理由，也不声称这就是所有官方版本/地区的完整列表。

## 其他入口的核对证据及适用范围

静态参考用户提供的官方 `com.phoenix.read` 7.4.3.32 APK。实际登录页 `PhoneNumberNormalView` 使用 `LoginPhoneAreaCodeConfig`；该配置的默认项为中国大陆 86（11 位）、中国香港 852（8 位）、中国澳门 853（8 位）。该类会读取服务端配置，因此默认项不能被描述为官方当前线上完整支持列表。

2026-11-10 补充只读联网核对：使用 APK 中的 `https://is.snssdk.com/service/settings/v3/` 设置入口，携带 `app=1`、`aid=8662`、`app_name=novelread`、`version_code=74332`、`version_name=7.4.3.32` 等匿名版本参数。响应 `data.settings.login_phone_area_code_config_v685.list` 本次仍为大陆 86/11 位、香港 852/8 位、澳门 853/8 位。该结果只代表此匿名请求上下文，不排除其他版本、地区或服务端分组拿到不同配置；不能据此保证短信送达。没有调用发码、验码或登录端点。

APK 的 `account_x_area_code.json` 是另一旧区号选择器使用的全球资料文件，不以其中的国家数量推断短信送达能力。本次未复制反编译代码或全球数据文件进仓库，不再以三个默认项作为所有登录入口的通用限制。

## 客户端修正

- 界面与核心共用截图可确认的 14 个区号。大陆与港澳有明确位数依据，其他地区只检查字符和国际号码总长度，不自行猜测当地号码位数或删除前导零；仍需按实际国际号码格式输入。
- 支持选择区号输入本地号码，也支持粘贴完整带 `+` 国际号码，带或不带空格、短横线均可。保留号码原有数字，不静默删除前导零或字母；位数不匹配、非法字符或不在列表的区号在请求前被拒绝。
- 请求受理提示不再声称短信已送达；即使顶层响应为 success，存在非零业务错误仍显示失败。
- 发码时号码与区号暂不可编辑；更换号码/区号后不得沿用旧验证码票据。保持已有发码冷却，不因切换区号自动发码或绕过冷却。
- 保持 App 通道，不切换网页；发码方式与字段编码按 App SDK 修正，身份兼容层暂保留，真实设备/会话差异仍未解决。

## 尚未验证的边界

用户确认持有人授权后，对指定号码仅进行一次 App 通道请求，平台仍返回错误码7，未受理；未读取或提交验证码，未自动重发，未记录号码或响应正文。该试验不能证明非大陆短信可达，运营商、平台风控及完整登录会话仍未验证。其他地区入口收敛不等于修好了该地区的收码故障，issue #98 应保留等待可验证反馈。

如果用户愿意继续反馈，只需提供区号、应用显示的脱敏错误提示，以及同一号码在官方 App 是否能收到短信；不需要公开手机号、验证码或会话。官方同样收不到与仅本客户端收不到，应分别判断，不以“可选区号”或“平台受理成功”代替送达证据。

## 本地验证

模拟请求覆盖截图 14 个区号的选择/格式边界、无分隔国际号码、未提供地区零网络请求、非法位数/字符、业务错误、缺少打码回显时的保护，以及 Android API 23/26 区号选择与更换号码后不提交旧票据。所有短信响应均由本地拦截器提供，不调用真实发码端点。

## 官方网页与当前 TV 发码通道的只读对照

2026-11-10 依据官方网页公开脚本（构建 `main.3575a0b3ce.js`，登录模块 `5.9af5d76850.js`，SDK 模块 `32.5d14166e52.js`）核对：截图对应的网页初始化 WebInterfaceSdk，aid 为 513755，打开 globalMobileSupport 并提供十四地区规则。台湾号码校验为去除本地拨号前导零后的九位；已按国际格式输入九位时，其 `+886 空格 号码` 拼接形式与 TV 当前格式一致，不应把该样本立即报错归因于分隔符或位数。

官方网页通过 `/passport/web/send_code/` 进行 POST 表单请求，登录发码 type 为 24，mobile/type 经 SDK mix_mode 编码；请求携带站点会话 Cookie 与 passport CSRF 处理。当前 TV 手机号面板实际调用 PhoneLogin，走 aid 8662、security.snssdk.com 的 `/passport/mobile/send_code/v1/`，在本次修正前以 GET 查询参数提交号码，沿用设备表身份且不回发 Cookie。两者是不同认证上下文；区号 UI 对齐不等于发码通道已经兼容。现有 WebLogin 虽有网页通道方法，但尚未接入这个手机号面板，也不据此直接切换或自动重试发码。

用户反馈官方可发而 TV 首次即返回“访问太频繁，错误码7”。代码一次点击只发起一次发码调用；这个平台拒绝提示不能据此认定用户连续发送。上述差异证明应继续调查请求兼容性，受控单次请求仍被拒绝，尚不能证明哪项差异导致错误7，也不能断言共享设备身份、地区政策或某个字段就是唯一根因。网页对照阶段仅下载公开脚本，没有执行网页发码、提交验证码或读取登录会话。

## 官方 App SDK 对照与单次授权试验

官方 7.4.3.32 APK 的账号 SDK 中，`gi1.g` 发码任务通过 `ai1.a` 构建 POST 请求。手机号、type、unbind_exist 经 StringUtils.encryptWithXor（UTF-8 字节 XOR 5 后十六进制）编码，带 mix_mode=1 和 auto_read；基础任务添加 account_sdk_source=app，SDK 版本 5051452 位于查询参数中。sms_login 与 sms_login_only 同样是 POST，并编码手机号与验证码。旧客户端 GET 明文发码不符合这段实现。

现修正上述请求构造，查询/UA/签名版本统一7.4.3.32，正文参与签名；移除不适用于未登录会话的 validate_code 兜底。禁止客户端网络自动重试与重定向，一次发码调用不自动重复或改走网页。官方 SDK 还会经运行时 NetworkParams 回调追加公共参数；目前的固定设备表、会话环境不能被描述为与真实 App 完全一致。

用户明确授权只发送一次。该次请求已实际发出一次，平台返回错误码7，没有报告受理成功，随后停止，没有试第二次或验码。请求方法/编码修正本身不足以解决本次拒绝。试验后继续静态核对，纠正了 SDK 版本参数的位置；最终构建未再次实号发码，不能将模拟测试通过写成海外短信已修复。

真实号码仅在试验进程内传入，不进入仓库或诊断输出；一次性执行标记防止重复运行。公开接码号码未使用。若继续调查，应对照官方 Android App 的合法设备/会话公共参数，而不能用网页通道的可用性断言 App 通道必然同样开放。
